## Scope and method

I read each PR's description and relevant changed calculation/policy source,
examined its available tests and documentation, and recorded the observation below.
I opened the source archive in #103, whose diff contains only a binary ZIP.
For service-heavy submissions, the focus was the fee core and its integration
contracts. Generated files, vendored dependencies, binaries and repetitive ORM
scaffolding were excluded. This is not a line-by-line audit of every file or a
review of every discussion comment.

The PRs were **not all built or executed**. The notes are source-review findings
and design tradeoffs, not a test-certified ranking of the submissions. Some PRs
intentionally interpret ambiguous requirements differently. The delivered C#
solution has its own documented choices and verification results.

Each row links to the PR and records its head SHA from the snapshot. A PR may
have changed since the review. No raw PR implementations or third-party packages
are bundled into this solution; the original repository license is preserved.

## Decisions that matter more than framework choices

1. **Anchored elapsed windows:** 06:59 and 07:01 belong together; clock-hour
   grouping would separate them. Later passages do not extend the window.
2. **Full precision:** 60 minutes is included, 60 minutes plus one tick is not.
   Tariff endpoints use the next band's start, avoiding fractional-second gaps.
3. **One vehicle/day:** validate the complete batch before exemptions and keep
   the 60 SEK cap local to that day. There is no mutable billing ledger.
4. **Explicit calendar coverage:** retain the supplied 2013 holiday/eve policy
   and July exemption. A public-holiday package alone is not a complete toll policy.
5. **Simple dependencies:** deterministic in-memory calculation needs no database,
   HTTP request, cache, logging framework, AI classification or asynchronous API.
